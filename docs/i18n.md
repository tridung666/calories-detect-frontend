# Đa ngôn ngữ

Project dùng [i18next](https://www.i18next.com/) và
[react-i18next](https://react.i18next.com/) cho tiếng Việt (`vi`) và tiếng Anh (`en`).

## Cấu trúc

- `src/locales/<language>/*.json`: nội dung dịch, chia theo namespace `common`,
  `auth`, `dashboard`, `meals`, `profile`, `admin`, `validation`, `errors`.
- `src/lib/i18n/config.ts`: danh sách ngôn ngữ, tên hiển thị và locale dùng định dạng.
- `src/lib/i18n/resources.ts`: đăng ký các namespace theo ngôn ngữ.
- `src/lib/i18n/i18next.d.ts`: kiểm tra khóa dịch bằng TypeScript.
- `src/app/providers/language-provider.tsx`: đồng bộ `html.lang`, hướng chữ,
  mô tả trang và lựa chọn đã lưu.

Ngôn ngữ được chọn theo thứ tự: lựa chọn đã lưu → ngôn ngữ trình duyệt được hỗ trợ
→ tiếng Việt. Lựa chọn được lưu vào `calories-detect-language` trong localStorage.
Nếu trình duyệt chặn storage, việc chuyển ngôn ngữ vẫn hoạt động trong phiên hiện tại.
Khóa dịch chưa có nội dung sẽ dùng bản tiếng Anh dự phòng.

## Viết UI

Dùng khóa có ý nghĩa; không viết trực tiếp câu chữ trong JSX, nhãn, placeholder,
aria-label, trạng thái trống, thông báo hoặc lỗi form. Giữ nguyên mã enum gửi API
(`BREAKFAST`, `ADMIN`, ...) và nội dung người dùng nhập.

```tsx
const { t } = useTranslation(["common", "meals"])

<Button>{t("common:actions.saveChanges")}</Button>
<p>{t("meals:count", { count: meals.length })}</p>
```

Khai báo namespace mà component sử dụng. Dùng nội suy thay vì nối các phần của câu.
Truyền `count` dạng số để i18next chọn số ít/số nhiều; bản tiếng Anh dùng hậu tố
`_one` và `_other`. Dùng `{{count, number}}` để định dạng số trong bản dịch.

Ngoài React (ví dụ callback thông báo thành công), gọi `i18n.t(...)` ngay lúc
hiển thị để dùng ngôn ngữ hiện tại. Không dịch một lần tại thời điểm import module.

`formatDate` và `formatNumber` trong `src/lib/format.ts` đọc locale hiện tại.
Component sử dụng các hàm này cần `useTranslation(...)` để cập nhật khi đổi ngôn ngữ.
Ngày trong input và dữ liệu API vẫn dùng định dạng ISO; đơn vị số và mã enum không thay đổi.

## Validation và lỗi API

Schema Zod lưu khóa bằng `validationKey("emailRequired")`. `FormInput` và
`FormSelect` dịch khóa khi render, nên lỗi đang hiển thị đổi ngôn ngữ mà không cần
reset form hay nhập lại dữ liệu. Thêm thông báo mới trong namespace `validation`.

`getApiErrorMessage` ánh xạ mã lỗi nghiệp vụ/HTTP tới namespace `errors` tại thời
điểm hiển thị. Khi thêm mã lỗi backend, bổ sung ánh xạ và bản dịch tương ứng.

## Thêm ngôn ngữ

1. Sao chép thư mục `src/locales/en` thành thư mục có mã ngôn ngữ mới, rồi dịch
   các giá trị. Giữ khóa và biến nội suy; bổ sung các dạng số nhiều mà ngôn ngữ cần.
2. Thêm mã, tên tự gọi của ngôn ngữ và locale vào `languageConfig`.
3. Import các tệp JSON và đăng ký trong `resources`. TypeScript sẽ kiểm tra các
   namespace và khóa bắt buộc.
4. Chạy `npm run test`, `npm run lint`, `npm run build` và `npm run test:e2e`.

Bộ chọn ngôn ngữ tự lấy danh sách từ cấu hình; không cần sửa component cho từng ngôn ngữ.
Các bản dịch hiện được bundle cùng ứng dụng. Khi số ngôn ngữ hoặc nội dung tăng lớn,
có thể thay lớp nạp resource bằng lazy loading mà giữ nguyên cách gọi `t` trong UI.

Kiểm thử ở `src/lib/i18n/i18n.test.ts` kiểm tra khóa/biến nội suy, lựa chọn ngôn ngữ,
số nhiều, fallback, lỗi và định dạng ngày/số. `e2e/i18n.spec.ts` kiểm tra luồng đổi
ngôn ngữ, dữ liệu form, lưu lựa chọn, các trang chính và giao diện mobile.
